## Брэнд, өнгөний систем

Дизайн бүхэлдээ **GEOid логоны өнгөнөөс** гаралтай. Логог `src/components/logo.tsx`
дотор вектор (SVG) хэлбэрээр дахин бүтээсэн тул ямар ч хэмжээнд тод харагдана —
хажуугийн цэс, нүүр хуудас, favicon (`src/app/icon.svg`) бүгд нэг эх сурвалжаас.

| Токен | Өнгө | Логон дээрх байрлал | Системд хаана |
|-------|------|---------------------|---------------|
| `geo` | `#1B9AD6` | «GE» үсэг | Үндсэн товч, идэвхтэй цэс, холбоос |
| `sun` | `#FA7314` | «id» үсэг, тойрог замын зүүн тал | Онцлох, товчийн шилжилтийн төгсгөл |
| `aqua` | `#2FB9D6` | тойрог замын баруун тал | Амжилт, батлагдсан төлөв |
| `amber` | `#FBA92A` | тойрог замын алтан шилжилт | Анхааруулга, **сонгон судлах цаг** |
| `ink` | `#3F6B7C` | ном, луужингийн шугам | Текст, хүрээ, нейтрал суурь |

Товчийн шилжилт (`.btn-primary`) болон хяналтын самбарын толгой (`.brand-gradient`)
нь логоны тойрог замын шилжилтийг давтдаг: цэнхэр → номин → алт → улбар шар.

Өнгө өөрчлөх бол `tailwind.config.ts` (шатлал) болон `src/app/globals.css`
(`:root` дахь `--geo`, `--sun`, `--aqua`, `--amber`, `--slate`) хоёрыг зэрэг засна.

> **Эх PNG логог ашиглах бол:** файлаа `public/logo.png` болгон хуулаад
> `src/components/logo.tsx` дотор `LogoMark`-ийн SVG-г
> `<img src="/logo.png" width={size} height={size} alt="GEOid" />` болгон солино.
> Бусад бүх хуудас автоматаар шинэчлэгдэнэ.

## 1. Supabase тохируулах

### 1.1 Төсөл үүсгэх

1. [supabase.com](https://supabase.com) → **New project**
2. Нэр, нууц үг, бүс (Region: `Southeast Asia (Singapore)` санал болгоно)
3. Төсөл бэлэн болтол 1–2 минут хүлээнэ

### 1.2 Өгөгдлийн сангийн схем оруулах

Supabase Dashboard → **SQL Editor** → **New query** дээр дараах файлуудыг **дарааллаар нь** бүтнээр хуулж ажиллуулна:

```
supabase/01_schema.sql     ← хүснэгт, төрөл, триггер
supabase/02_rls.sql        ← аюулгүй байдлын бодлого (RLS)
supabase/03_seed.sql       ← афоризм болон эхлэлийн өгөгдөл
supabase/04_demo_data.sql  ← жишээ өгөгдөл (заавал биш, эхний менежер батлагдсаны дараа)
```

### 1.3 Түлхүүр авах

**Project Settings → API** хэсгээс:

| Хувьсагч | Хаанаас |
|----------|---------|
| `NEXT_PUBLIC_SUPABASE_URL` | Project URL |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | `anon` `public` түлхүүр |
| `SUPABASE_SERVICE_ROLE_KEY` | `service_role` `secret` түлхүүр |

> ⚠️ `service_role` түлхүүрийг **хэзээ ч** клиент код, GitHub-д байршуулж болохгүй. Зөвхөн Vercel-ийн Environment Variables-д хадгална.

### 1.4 И-мэйл баталгаажуулалт (сонголт)

**Authentication → Providers → Email** хэсэгт `Confirm email` тохиргоог:
- **Асаалттай** — хэрэглэгч и-мэйлээ баталгаажуулна (аюулгүй)
- **Унтраалттай** — шууд бүртгүүлнэ (тест хийхэд хялбар)

Аль ч тохиолдолд системд орохын тулд **админ баталсан** байх ёстой.

## 4. Vercel-д deploy хийх

1. [vercel.com](https://vercel.com) → **Add New → Project** → GitHub repo-гоо сонгоно
2. Framework: **Next.js** (автоматаар танина)
3. **Environment Variables** хэсэгт 3 хувьсагчаа нэмнэ:

   | Name | Value |
   |------|-------|
   | `NEXT_PUBLIC_SUPABASE_URL` | `https://xxxx.supabase.co` |
   | `NEXT_PUBLIC_SUPABASE_ANON_KEY` | `eyJhbG...` |
   | `SUPABASE_SERVICE_ROLE_KEY` | `eyJhbG...` |

4. **Deploy** дарна

### Supabase-д домэйн бүртгэх

Deploy дууссаны дараа Supabase → **Authentication → URL Configuration**:

- **Site URL**: `https://<таны-төсөл>.vercel.app`
- **Redirect URLs**: `https://<таны-төсөл>.vercel.app/**`

## 5. Анхны админ үүсгэх

1. Вэб сайтын `/register` хуудсаар бүртгүүлнэ
2. Supabase → **SQL Editor** дээр:

```sql
update profiles
   set role = 'admin', status = 'approved', approved_at = now()
 where email = 'ТАНЫ_ИМЭЙЛ@example.com';
```

3. Дахин нэвтрэхэд `/admin` хуудас нээгдэнэ

Үүнээс хойш бусад менежерүүдийг вэб дээрээс шууд батлах боломжтой.

## Ашиглах дараалал

```
1. Тохиргоо      → Судлагдахуун, анги, кабинет, ээлж, цалингийн үзүүлэлт
2. Багшийн бүртгэл → Багш + кабинетийн эрэмбэ (1–7) + долоо хоногийн ачаалал
3. Хичээлийн хуваарь → «Хуваарь зохиох» → шалгах → Excel татах
4. Төлөвлөгөө    → Жил/улирал/сар/7 хоногийн ажил
5. Ажлын гүйцэтгэл → Төлөвлөгөөнөөс багш нарт оноох, чеклэх, дүгнэх
6. Цаг, цалин    → «Хуваариас бөглөх» → цаг засварлах → цалин бодох
7. Ажиглалт      → Хичээлд суусан тэмдэглэл
8. Дүнгийн матриц → Сурагч нэмэх → дүн оруулах → нэгтгэл
```

### Чухал: кабинетийн эрэмбэ

Багшийн бүртгэлд **1-р байранд бичсэн кабинет** нь тухайн багшийн хувьд бусад багш нараас **давуу эрхтэй** — хуваарь зохиоход эхэлж энэ кабинетэд оруулна. 2-оос 7 хүртэлх кабинетууд эрэмбийн дагуу нөөц болно.

### Под группийн хичээл

Тохиргоо → Судлагдахуун дээр **«Под группээр хуваагдана»** гэж тэмдэглэсэн хичээл (Англи хэл, эрэгтэй/эмэгтэй технологи) нь заавал **зэрэгцэж**, нэг ангийн хоёр групп нэг цагт орно.

Багшийн ачаалал оруулахдаа тухайн ангийн хоёр группийг **Групп A / Групп B** гэж тэмдэглэнэ.

### Биеийн тамир

Тохиргоо → Кабинет дээр танхимыг **«Заал»** гэж тэмдэглэвэл, хуваарь зохиоход **нэг зааланд 2 анги** зэрэг орно. Систем үе ойролцоо ангиудыг (жишээ нь 7а + 7б) хамтад нь хуваарилахыг эрхэмлэнэ.

## Хуваарь зохиох алгоритм

`src/lib/scheduler.ts` — хязгаарлалтад суурилсан (constraint-based) шийдэгч.

### Хатуу хязгаарлалт (заавал хангагдана)

- Нэг багш нэг үед зөвхөн нэг ангид
- Нэг анги нэг үед зөвхөн нэг хичээл (под групп үл хамаарна)
- Нэг кабинетэд нэг үед нэг хичээл — заал 2 ангийг багтаана
- 7 хоногийн нийт цаг **яг** таарна
- Под группийн хичээл заавал зэрэгцэнэ

### Зөөлөн шалгуур (оноогоор эрэмбэлэгдэнэ)

| Шалгуур | Оноо |
|---------|------|
| Багшийн 1-р кабинет | +70 (2-р нь +60 … 7-р нь +10) |
| Кабинет таарахгүй | −25 |
| Нэг хичээл нэг өдөр давтагдах | −45 |
| Өглөөний эхний цаг | +4 / цаг |
| Ангийн хичээл цуварсан | +12 / +8 |
| Багшид цонх үүсэхгүй | +10 / +6 |
| Заал хуваалцсан анги үе ойролцоо | +30 хүртэл |

### Ажиллах зарчим

1. Ачааллыг байрлуулах **нэгж** болгон задална (под групп → хос нэгж, заал → хос нэгж)
2. Хамгийн **хязгаарлагдмал** нэгжийг эхэлж байрлуулна
3. Боломжит (өдөр, цаг) бүрд оноо тооцож хамгийн өндөрийг сонгоно
4. Санамсаргүй эхлэлтэйгээр **N удаа** давтаж хамгийн сайныг үлдээнэ

### Туршилтын үр дүн

18 багш · 18 анги · 17 кабинет · 418 цаг/7 хоног:

```
Байрласан цаг:       418 / 418
Хатуу зөрчил:        0
Под группийн зэрэгцэл: 72/72 хос
Заал хуваалцалт:     18 хос (үеийн зөрүү дундаж 0.33)
1-р кабинет таарсан: 94.0%
Хугацаа:             84мс
```

Нөөц хүрэлцэхгүй тохиолдолд систем **хэзээ ч буруу хуваарь гаргахгүй** — багтаагүй цагийг шалтгаантай нь жагсаан харуулна.

## Аюулгүй байдал

- **Row Level Security** — менежер бүр зөвхөн өөрийн өгөгдлийг харна (`owner_id = auth.uid()`)
- Батлагдаагүй хэрэглэгч ямар ч өгөгдөлд хандахгүй (`is_approved()` шалгалт)
- Админ бүх өгөгдлийг харна
- `owner_id` нь өгөгдлийн сангийн триггерээр автоматаар онооно — клиентээс хуурах боломжгүй
- Middleware нь эрхгүй хуудсуудыг сервер талд хаана
- Хэрэглэгч өөрийн `role` / `status`-аа өөрчилж чадахгүй (RLS `with check`)
- Админы үйлдлүүд server action дотор дахин эрх шалгана
- Бүх админ үйлдэл `audit_log`-д бүртгэгдэнэ

## Тусламж

**«Хуваарь зохиох» дарахад «ачаалал оруулаагүй» гэнэ**
→ Багшийн бүртгэл → багш засах → «Хичээл ордог анги ба долоо хоногийн цаг» хэсэгт мөр нэмнэ.

**Хуваарь зохиогдсон ч зарим цаг байрлаагүй**
→ Кабинет цөөн, эсвэл өдрийн цагийн тоо хүрэлцэхгүй байна. Тохиргоо → Ээлж дээр «Өдрийн цагийн тоо»-г нэмэх, эсвэл кабинет нэмнэ.

**Нэвтэрсэн ч /pending хуудас руу шиднэ**
→ Админ таны бүртгэлийг баталгаажуулаагүй байна.

**Excel татахад алдаа гарна**
→ Хөтчийн татах зөвшөөрлийг шалгана уу.
